> **ОБЯЗАТЕЛЬНО:** Каждую новую задачу начинай с прочтения этого файла целиком.
> Затем проверь `.claude/CHANGELOG.md` чтобы понять что уже сделано.

---

## О проекте

Юмористический веб-сайт о жизни программиста. Включает несколько мини-игр и интерактивных разделов.
Стек: **PHP 8.x + SQLite + jQuery + Vanilla JS + CSS без фреймворков**.
Среда разработки: **OSPanel** (локальный сервер на Windows).

## Правила разработки

### Общие

1. **Читай этот файл перед каждой задачей** — сначала CLAUDE.md, потом CHANGELOG.md, потом код.
2. **Читай существующий код перед изменениями** — не модифицируй то, чего не читал.
3. **Минимум изменений** — делай ровно то, что просят. Не рефакторь попутно, не добавляй «улучшения».
4. **Не создавай лишних файлов** — предпочитай редактировать существующие.
5. **Не добавляй комментарии** к коду который не менялся. Комментарии только там, где логика неочевидна.
6. **После каждого изменения** — добавляй запись в `.claude/CHANGELOG.md`.
7. **После завершения задачи** — коммить и пушь изменения через агент-скрипт (см. ниже).

### PHP

- `declare(strict_types=1)` в начале каждого файла.
- `session_start()` + `require_once __DIR__ . '/db.php'` там где нужна сессия/БД.
- Все выводы пользовательских данных через `htmlspecialchars()`.
- AJAX-эндпоинты возвращают `Content-Type: application/json`.
- Пароли хранить через `password_hash(..., PASSWORD_BCRYPT)`.
- После логина делать `session_regenerate_id(true)`.

### JavaScript / jQuery

- Проект использует **jQuery 3.7.1** (CDN) на всех страницах.
- Не подключать дополнительные JS-фреймворки без необходимости.
- AJAX-запросы к `/ajax/*.php` через `fetch()` или `$.ajax()`.
- Данные игры хранить в `localStorage` (для гостей) и синхронизировать с сервером (для залогиненных).

### CSS

- Без CSS-фреймворков (нет Bootstrap, Tailwind и т.д.).
- Каждая страница имеет свой CSS-файл в `/css/`.
- Шрифты: `JetBrains Mono` (код/терминал) + `Inter` (UI).
- Иконки: Font Awesome 6.5.1 (CDN), подключается там где нужно.

### Безопасность

- Все AJAX-эндпоинты проверяют сессию перед действием.
- Числовые значения от клиента кэпать на сервере (пример: `min($bugs, 100)`).
- Не доверять клиентским данным — валидировать на сервере.
- SQL только через PDO prepared statements.

### Нерешённое / заглушки

- `pvp.php` — ссылка на «⚔️ Арена» есть в навигации `idle.php`, но файл **не создан**.

## Завершение задачи — коммит и пуш

После выполнения **каждой задачи** обязательно:

1. Добавить запись в `.claude/CHANGELOG.md` (новые записи сверху).
2. Запустить скрипт-агент коммита:

```bash
bash .claude/push.sh "тип: краткое описание что сделано"
```

**Примеры сообщений коммита:**
```bash
bash .claude/push.sh "feat: добавлена страница pvp арены"
bash .claude/push.sh "fix: исправлен баг с сохранением прогресса"
bash .claude/push.sh "refactor: переработана логика престижа"
bash .claude/push.sh "style: обновлены стили idle-игры"
```

**Что делает скрипт `.claude/push.sh`:**
- Стейджит все изменения (`git add -A`)
- Исключает `db/game.sqlite` и `logs/` (не коммитить)
- Создаёт коммит с переданным сообщением
- Пушит в `origin main`
- Если изменений нет — сообщает об этом и завершается без ошибки
