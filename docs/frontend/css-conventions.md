# CSS Conventions

## Цель

Сделать стили проекта предсказуемыми без перехода на build step или CSS framework.

## Базовые правила

- Общие design tokens живут в `css/tokens.css`.
- Страничные CSS-файлы сначала подключают `tokens.css`, потом задают только локальные overrides.
- Новые цвета, радиусы, тени и шрифты не хардкодятся в компонентах без явной причины.
- Повторяющиеся primitive-значения сначала переводятся в CSS custom properties, потом уже размножаются по селекторам.

## Именование токенов

- `--bg*` для слоёв фона
- `--border*` для границ и разделителей
- `--text`, `--dim` для типографики
- `--accent`, `--accent2`, `--purple`, `--red`, `--yellow`, `--green`, `--blue` для функциональных цветов
- `--radius`, `--radius-lg` для скруглений
- `--shadow`, `--shadow-lg`, `--glow-*` для теней и свечения
- `--transition` для типового интерактивного перехода

## Практика по файлам

- `css/tokens.css` содержит только общие токены, без компонентных селекторов.
- `css/auth.css`, `css/idle.css`, `css/style.css`, `css/game.css`, `css/dungeon.css`, `css/minigame.css` могут переопределять токены в своём `:root`, если страница реально отличается по теме.
- Если страница использует ту же тему, что и остальные, локальный `:root` лучше не дублировать.

## Что не делать

- Не вводить новые nearly-duplicate токены вроде `--text-muted-2`, если уже подходит `--dim`.
- Не размазывать page-specific цвета по нескольким файлам без причины.
- Не превращать CSS в utility framework вручную.

## Следующий уровень

Если фронтенд продолжит расти, следующий безопасный шаг:

- выделить `css/base.css` для reset/scrollbars/body defaults
- затем вынести shared component primitives вроде `.page-nav`, `.nav-link`, `.btn-*`, `.card-*`
