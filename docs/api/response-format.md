# Формат API-ответов

## Цель

AJAX-эндпоинты проекта должны отвечать в предсказуемом формате, при этом существующий фронтенд не должен ломаться.

## Базовый контракт

Успешный ответ:

```json
{
  "success": true,
  "data": {},
  "error": null,
  "meta": {}
}
```

Ответ с ошибкой:

```json
{
  "success": false,
  "data": null,
  "error": "Текст ошибки",
  "meta": {}
}
```

## Совместимость с текущим фронтендом

Пока проект использует legacy JS, `ApiResponse::success()` дополнительно дублирует поля `data` на верхний уровень ответа.

Пример:

```json
{
  "success": true,
  "data": {
    "username": "alice",
    "csrfToken": "..."
  },
  "error": null,
  "meta": {},
  "username": "alice",
  "csrfToken": "..."
}
```

Это позволяет:

- постепенно переводить frontend на `response.data`
- не ломать текущие проверки вида `if (data.success)` и обращения к `data.username`

## Правила

- `success` обязателен всегда
- `error` в успешном ответе должен быть `null`
- `data` в ответе с ошибкой должен быть `null`
- `meta` предназначен для технической информации, например `retryAfter`
- HTTP status code должен соответствовать типу ошибки, но frontend не должен зависеть только от него
