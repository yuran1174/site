# Система сезонного ивентинга

## Задача

Нужна основа для регулярного контента без полной немедленной реализации. Система должна позволять запускать ограниченные по времени события, не ломая базовый idle loop и не превращая каждое событие в отдельный хардкод.

## Продуктовая проблема

Сейчас проект хорошо держит короткую и среднюю прогрессию, но ему не хватает причин возвращаться к уже освоенному аккаунту кроме очередного prestige cycle. Сезонный контент должен давать:

- новый повод открыть игру
- временную вариацию правил
- ограниченные награды
- безопасный live-ops контур без pay-to-win

## Цели системы

- задавать событие данными, а не ветвлением по датам в коде
- менять награды и правила без переписывания базовой логики
- поддерживать одновременно только один активный сезон на ранней стадии
- связывать события с уже существующими активностями: idle, minigame, dungeon, prestige

## Что такое сезонное событие

Сезонное событие это временный модификатор продукта со своими:

- датами старта и конца
- тематикой
- rule modifiers
- event missions
- наградами
- визуальными метками

Это не отдельная игра. Это временный слой поверх существующего продукта.

## Базовая модель

### 1. Season Definition

Поля:

- `id`
- `title`
- `theme`
- `startsAt`
- `endsAt`
- `status`: `scheduled`, `active`, `ended`
- `entryRequirement`
- `uiBadge`

### 2. Rule Modifiers

Позволяют временно менять базовые коэффициенты.

Примеры:

- бонус к награде minigame
- бонус к dungeon clear rewards
- дополнительный шанс good events
- временный multiplier для конкретной категории зданий
- сезонные event weights

Ограничение:

- modifiers не должны ломать prestige pacing
- modifiers должны быть временными и читаемыми игроку

### 3. Event Missions

Это набор сезонных задач.

Примеры:

- поймать `N` багов в minigame за сезон
- сделать `X` престижей
- пройти dungeon `Y` раз
- заработать `Z` ЛОК за сезон

Роль:

- давать среднесрочную цель на несколько сессий

### 4. Rewards

Сезонные награды делятся на три слоя.

Постоянные:

- бейджи
- достижения
- косметические теги профиля

Временные:

- сезонный multiplier на текущий сезон
- временные title/badge

Экономические:

- ЛОК
- ОО
- event tokens для будущего event shop

Правило:

- постоянные power rewards должны быть умеренными
- события не должны становиться обязательной meta-power дверью

## Рекомендуемая архитектура конфигов

На следующем шаге систему стоит положить в data/config слой такого вида:

```text
data/game/events/
  seasons.json
  modifiers.json
  missions.json
  rewards.json
```

Или в одном файле:

```text
data/game/seasonal-events.json
```

Минимальный runtime-контракт:

- получить активный сезон по текущей дате
- применить его modifiers
- отдать UI карточку сезона
- передать reward hooks в existing systems

## Reward Hooks

Событие должно встраиваться в существующие точки наград.

### Idle

- seasonal bonus к отдельным building categories
- бонусные random events
- сезонные mission counters

### Prestige

- сезонные задачи на число престижей
- ограниченный bonus payout только в safe cap

### Minigame

- миссии на число пойманных багов
- bonus chance на event token

### Dungeon

- миссии на число clear
- seasonal modifiers на reward chest

## Unlock Rules

Сезон не должен требовать отдельной страницы на старте.

Рекомендуемый baseline:

- первый сезон доступен всем аккаунтам
- отдельные advanced missions могут требовать `account level >= 5`
- high-value seasonal rewards могут требовать хотя бы один престиж

## Failure States

- событие слишком щедрое и ломает экономику
- событие слишком слабое и не даёт мотивации возвращаться
- событие спрятано слишком глубоко и его не замечают
- каждая новая тема требует ручного переписывания UI и наград

## Balance Risks

- Нельзя делать сезон лучшим источником ОО на длинной дистанции.
- Нельзя завязывать обязательный core progression на ограниченные по времени окна.
- Нельзя вводить эксклюзивную силу, которая делает пропуск сезона наказанием.

## Рекомендованный первый сезон

Тема:

- `Дедлайн-марафон`

Модификаторы:

- `+20%` к награде minigame
- `+1` guaranteed good event из сезонной цепочки в день

Миссии:

- поймать 50 багов
- пройти 3 dungeon run
- сделать 1 престиж за сезон

Награды:

- сезонный бейдж
- немного ЛОК
- немного ОО
- косметический title в профиле

Почему это безопасно:

- усиливает уже существующие режимы
- не требует новой отдельной боевой системы
- не ломает базовую мета-экономику

## Что делать дальше

- держать сезонный контент как конфиг, а не как новую страницу
- сначала добавить общий active-season resolver и reward hooks
- только потом выводить сезон как видимую активность в idle UI
